Projet : Visu_enquete_mesusage_pharma - Application de visualisation des données d’une enquête des mésusages observés au comptoir par les pharmaciens de ville

Fonctionnement technique de l’application

Cette section décrit le fonctionnement technique de l’application : les fichiers impliqués, les fonctions appelées et leur rôle. Elle se concentre sur l’onglet MEDOC_REG (les deux autres onglets suivent la même logique).

Fonctionnement général de Shiny appliqué à cette application

Dans une application R Shiny, le code est structuré selon une architecture proche du patron Modèle - Vue - Serveur (MVC) :

  • l’objet ui gère l’affichage (la Vue) : structure HTML, mise en page, thème, navigation ;
  • la fonction server gère la logique métier et la réactivité (le Contrôleur / Modèle) : chargement des données, calculs, réponses aux actions de l’utilisateur.

1. L’objet ui (User Interface — Interface Utilisateur)

L’objet ui définit la structure visuelle, la mise en page HTML, le thème et la navigation de l’application.

  • Structure globale (page_navbar) :
    • crée une barre de navigation en haut de page, identifiée par id = "main_navbar" ;
    • applique un thème Bootstrap 5 personnalisé (bslib::bs_theme, bootswatch “flatly”, couleur primaire verte #18bc9c) ;
    • injecte le CSS personnalisé (custom.css) via le header.
  • Onglet « Accueil » (nav_panel("Accueil", ...)) :
    • affiche une carte (card) structurée sur une grille fluide (fluidRow) ;
    • présente trois cartes de raccourcis (shortcut-card) avec icônes et boutons d’action (actionButton : go_medoc, go_lib_code_atc, go_focus).
  • Onglets applicatifs (nav_panel) :
    • MEDOC_REG, LIB_CODE_ATC et FOCUS_IPP_LAXA_CORTICO ;
    • chaque onglet intègre la partie visuelle d’un module Shiny (via mod_*_ui(...)), ce qui permet d’isoler l’interface de chaque registre.

2. La fonction server (logique applicative et réactivité)

La fonction server reçoit trois arguments (input, output, session) et définit les comportements dynamiques de l’application en réponse aux actions de l’utilisateur.

  • Gestion de la navigation dynamique (observeEvent) :
    • écoute les clics sur les boutons de la page d’accueil (input$go_medoc, input$go_lib_code_atc, input$go_focus) ;
    • utilise bslib::nav_select() pour basculer automatiquement l’affichage vers l’onglet correspondant dans la barre de navigation main_navbar.
  • Exécution de la logique métier (mod_*_server) :
    • appelle les fonctions serveurs de chaque module (mod_medoc_reg_server, mod_lib_code_atc_server, mod_focus_ipp_laxa_cortico_server) ;
    • ces modules gèrent le chargement des données Excel associées et le traitement dynamique des tableaux ou graphiques affichés dans la ui.

En résumé

  ┌─────────────────────────┐        Clics (input$go_medoc...)         ┌────────────────────────────┐
  │           UI            │ ───────────────────────────────────────> │           SERVER           │
  │                         │                                          │                            │
  │ • Structure Bootstrap   │ <─────────────────────────────────────── │ • Écoute les événements    │
  │ • Navigation & Cartes   │       Changement d'onglet actif          │ • Appelle les serveurs     │
  │ • Appel des modules UI  │          (bslib::nav_select)             │   de modules               │
  └─────────────────────────┘                                          └────────────────────────────┘

Règle de travail : si vous souhaitez modifier l’agencement d’un écran ou ajouter un nouvel onglet, tout se passe côté ui. Pour ajouter du traitement de données ou réagir à une action utilisateur, cela se gère dans le server.

Démarrage de l’application (app.R)

  1. Les packages sont chargés : shiny, bslib, shinycssloaders.
  2. Le thème est construit avec bslib::bs_theme(version = 5, bootswatch = "flatly", primary = "#18bc9c").
  3. La feuille de style custom.css est référencée via tags$head(tags$link(...)).
  4. page_navbar() crée 5 onglets : Accueil, MEDOC_REG, LIB_CODE_ATC, FOCUS_IPP_LAXA_CORTICO, ORIGINE MÉSUSAGE.
  5. La page Accueil affiche des cartes cliquables (shortcut-card) avec des actionButton : go_medoc, go_lib_code_atc, go_focus, go_origine.
  6. Dans le serveur, observeEvent() sur ces boutons appelle bslib::nav_select() pour basculer vers l’onglet correspondant.
  7. Chaque onglet est branché sur son module : mod_medoc_reg_server("medoc"), etc. L’UI de l’onglet est injectée via mod_medoc_reg_ui("medoc").

Module MEDOC_REG (R/mod_medoc_reg.R)

1. UI : mod_medoc_reg_ui(id)

L’écran est organisé en deux zones : - Zone supérieure (classe CSS .zone-tableau) : contient un uiOutput("etat") (message d’alerte si le fichier est absent) et un DTOutput("table_dci") (le tableau des DCI). - Zone inférieure (classe CSS .zone-graphiques) : titre « Détail de la DCI sélectionnée », un uiOutput("plot_msg"), puis un fluidRow contenant 7 cartes graphiques, chacune dans un bloc responsive Bootstrap 5 : - col-12 (très petit écran → 1 graphique/ligne) ; - col-md-6 (écran moyen → 2/ligne) ; - col-xl-4 (grand écran → 3/ligne).

Chaque carte est une div.graph-card contenant un plotly::plotlyOutput(...) de hauteur fixe 640 px, sauf la carte 6 (facteurs) dont la hauteur est pilotée dynamiquement :

Carte plotlyOutput Contenu
1 plot_genre Camembert du genre des patients (Homme / Femme / Autre).
2 plot_enceinte Camembert des données « enceinte » (Oui / Non / Non renseigné).
3 plot_age Barres horizontales des âges (2 niveaux hiérarchiques).
4 plot_origine Barres horizontales de l’origine du mésusage.
5 plot_type Barres horizontales du type de mésusage (2 niveaux).
6 plot_facteur Barres horizontales des facteurs. Précédé d’une checkboxInput("facteur_afficher_tous") + uiOutput("plot_facteur_ui").
7 plot_type_prise Barres horizontales du type de prise (2 niveaux).

2. Server : mod_medoc_reg_server(id)

2.1 Chargement des données (réactives)
  • medoc_reg() : appelle read_medoc_reg() (depuis R/read_data.R) une seule fois au démarrage du module. En cas d’erreur (tryCatch), renvoie NULL.
  • principaux_facteurs() : appelle read_principaux_facteurs() et charge le second fichier principaux_facteurs.xlsx (nécessaire au 6e graphique), au même moment que MEDOC_REG.xlsx.
2.2 Tableau des DCI
  • dci_df() : à partir de medoc_reg(), filtre les lignes Type_donnee == "effectif", exclut la ligne agrégée "Total" (périmètre global, pas une substance), ne conserve que DCI et Total, puis trie par effectif décroissant.
  • output$table_dci (renderDT) : génère le tableau avec DT::datatable(). Caractéristiques :
    • selection = "single" → une seule ligne sélectionnable à la fois ;
    • colnames renomme DCI → « Substance (DCI) » et Total → « Effectif total » ;
    • pageLength = 15 et libellés en français (plugin i18n).
  • output$etat (renderUI) : affiche une alerte Bootstrap (.alert.alert-warning) si la donnée est NULL (fichier introuvable/illisible).
2.3 Sélection d’une DCI (enchaînement)
  1. selected_dci() : lit input$table_dci_rows_selected (index de la ligne cliquée dans DT). Renvoie le nom de la DCI (dci_df()$DCI[idx]), ou NULL si aucune ligne n’est sélectionnée.
  2. selected_genre() : à partir de medoc_reg() et de la DCI sélectionnée, filtre la ligne Type_donnee == "effectif" correspondante et renvoie cette ligne (utilisée notamment pour le genre et l’enceinte).
  3. output$plot_msg (renderUI) : si aucune DCI → message « Cliquez sur une DCI du tableau ci-dessus… ». Sinon, affiche un titre .dci-title avec le nom de la DCI.
2.4 Les 7 graphiques (réactives de données puis rendus Plotly)

Le schéma général : une réactive construit une dataframe « propre » (libellés, effectifs, pourcentages), puis un renderPlotly la transforme en graphique. S’il n’y a ni DCI sélectionnée ni données, chaque render renvoie plotly::plotly_empty().

Graphique 1 — Genre des patients (plot_genre)
  • genre_values() : lit les colonnes par index 5 (Homme), 6 (Femme), 7 (Autre) de la ligne selected_genre(). Les NA → 0, les segments d’effectif nul sont écartés. Le pourcentage est recalculé sur le total Homme + Femme + Autre et formaté en français (formatC, virgule décimale, 1 décimale).
  • output$plot_genre : plotly::plot_ly(type = "pie"). Couleurs via genres_colors() (R/colors.R). Étiquette par secteur : Libellé<br>Effectif (Pourcentage %). Infobulle : Libellé / Effectif : … / Pourcentage : … % (via customdata).
Graphique 2 — Données « enceinte » (plot_enceinte)
  • enceinte_values() : lit les colonnes par index 8 (Non), 9 (Oui), 10 (Non renseigné). Le pourcentage est recalculé sur le total enceinte (Non + Oui + Non renseigné), formaté en français.
  • output$plot_enceinte : camembert en nuances de vert via enceinte_colors() (R/colors.R). Même logique d’étiquette et d’infobulle que le graphique 1.
Graphique 3 — Âges (plot_age) — 2 niveaux hiérarchiques
  • age_values() : filtre la ligne effectif de la DCI sélectionnée, puis construit une hiérarchie codée en dur avec les libellés affichés et leurs indices de colonnes (K→T, soit 11 à 20) :
    • Niveau 1 (groupe, en gras) : Total ENFANTS et ADOLESCENTS / Total ADULTES ;
    • Niveau 2 (détails, non gras, indentés de 4 espaces, ex. « Nouveau né ou nourrisson (0-23 mois) »).
    • La colonne « ST JEUNES, ENFANTS » est volontairement ignorée.
    • Deux totaux sont calculés : total_mol (colonne 4 de la ligne « effectif » de la DCI) et total_ens (colonne 4 de la ligne agrégée « Total » ; si absent, retombée sur total_mol).
    • Pour chaque libellé, deux rangées sont générées : Mode = "molécule" (Pct = effectif/total_mol) puis Mode = "ensemble des cas" (Pct = effectif/total_ens). Un caractère invisible \u200B est ajouté au libellé de la seconde barre pour que Plotly distingue deux catégories d’axe Y visuellement identiques.
    • Couleurs : groupes en bordeaux (#8b1e2d), détails en bordeaux clair (#c98792) pour le mode molécule ; groupes en orange (#e2800f), détails en orange clair (#e4b279) pour le mode ensemble des cas (voir age_colors() et age_colors_ensemble()).
  • output$plot_age : construit 4 traces Plotly (bar, orientation = "h") selon les combinaisons Mode × Type (légende : « Molécule — groupe », « Molécule — détail », « Ensemble des cas — groupe », « Ensemble des cas — détail »). Axe Y inversé pour une lecture de haut en bas, barmode = "overlay". Chaque barre porte sa valeur en % ; l’infobulle affiche libellé propre, effectif et pourcentage via customdata.
Graphique 4 — Origine du mésusage (plot_origine)
  • origine_values() : lit les colonnes 21 à 23 (U, V, W : prise / prescription / dispensation). Toutes les modalités sont de niveau detail. Même double calcul molécule / ensemble des cas que le graphique 3.
  • output$plot_origine : mêmes 4 traces et mêmes couleurs que plot_age, mais configurées pour les 3 modalités d’origine.
Graphique 5 — Type de mésusage (plot_type) — 2 niveaux hiérarchiques
  • type_values() : lit les colonnes 40 à 50 (AN→AX). Hiérarchie codée en dur :
    • Niveau 1 (groupe, gras) : Total Posologie, Fréquence, durée (col. 40) et Total Indication, population, CI (col. 45) ;
    • Niveau 2 (détails) : Schéma posologique non conforme (41), Arrêt prématuré (42), Prolongation durée TT (43), Voie d’administration non conforme (44), Indication hors AMM (46), Population non prévue (47), Contre-indications (48), Interaction médicamenteuse (49), Autre (50).
    • Double calcul molécule / ensemble des cas comme le graphique 3.
  • output$plot_type : mêmes 4 traces et couleurs.
Graphique 6 — Facteurs de mésusage (plot_facteur) — fichier principaux_facteurs.xlsx
  • facteur_values() :
    • Récupère total_mol (col. 4 de la ligne « effectif » de la DCI) et total_ens (ligne « Total »).
    • Recherche la colonne dédiée à la DCI parmi les colonnes 135:147 (EE→EQ) de principaux_facteurs : l’en-tête (ligne 2) de chaque colonne contient le nom de la DCI. Si aucune colonne ne correspond → NULL.
    • Sélectionne les lignes effectif (colonne C == “effectif”) en écartant l’en-tête (lignes ≤ 2) et la première ligne (agrégée).
    • Applique le mapping des libellés courts (du cahier des charges, ex. « Manque d’info. ou com. interprofessionnelle ») par position (ordre du fichier = ordre de la référence), pour robustesse vis-à-vis des espaces insécables.
    • Calcule eff_dci (valeur dans la colonne de la DCI) et eff_global (colonne 4, “Total”).
    • Trie par pourcentage décroissant (critère = barre molécule).
    • Génère, pour chaque facteur, deux barres : molécule puis ensemble des cas (avec \u200B).
  • facteur_height() : hauteur de la carte selon l’état de la checkbox : 820px (15 premiers facteurs) ou 1000px (déplié, 29 facteurs).
  • facteur_plot_data() : extrait de facteur_values() le sous-ensemble tracé : 30 lignes (15 facteurs × 2 barres) par défaut, ou la totalité (58 = 29 × 2) si la case est cochée. Les données étant déjà triées par % décroissant, garder les premières lignes = garder les 15 plus grands pourcentages.
  • output$plot_facteur_ui (renderUI) : injecte plotlyOutput("plot_facteur") avec la hauteur issue de facteur_height().
  • output$plot_facteur : barres horizontales avec textposition = "outside" et outsidetextfont de taille 17 pour que les pourcentages restent lisibles même en mode déplié ; axe X range = c(0, 115). Tous les facteurs sont de Type = "detail" (pas de hiérarchie).
Graphique 7 — Type de prise (plot_type_prise) — 2 niveaux hiérarchiques
  • type_prise_values() : lit les colonnes 24 à 30 (X→AD). Hiérarchie codée en dur :
    • Niveau 1 (groupe, gras) : Prise avec ordonnance (col. 24) et Prise sans ordonnance (col. 27) ;
    • Niveau 2 (détails) : Primo prescription (25), Renouvellement (26), Sans ordo en automédication (28), Sur conseil du pharmacien (29), Je ne sais pas (30).
    • Double calcul molécule / ensemble des cas.
  • output$plot_type_prise : mêmes 4 traces et couleurs.

2.5 Couleurs et CSS

Les couleurs sont définies deux fois, de façon cohérente : - Dans www/custom.css (bloc :root) : variables CSS --couleur-homme (rgb(0,70,103)), --couleur-femme (rgb(45,131,14)), --couleur-autre (rgb(255,149,43)), --couleur-groupe (#8b1e2d), --couleur-detail (#c98792), --couleur-groupe-ensemble (#e2800f), --couleur-detail-ensemble (#e4b279), et les nuances d’enceinte (--couleur-enceinte-oui/non/nr). - Dans R/colors.R : helpers R genres_colors(), age_colors(), age_colors_ensemble(), enceinte_colors() qui reflètent ces mêmes valeurs (nécessaire car Plotly ne lit pas les variables CSS).

2.6 Retour exposé du module

À la fin de mod_medoc_reg_server(), un list(...) renvoie les réactives internes (ex. dci_df, medoc_reg, principaux_facteurs, selected_dci, facteur_values, facteur_plot_data, facteur_height) afin de permettre les tests via shiny::testServer. Ce retour est inoffensif en production (ignoré par shiny::runApp).

Récapitulatif du cycle de traitement de l’onglet MEDOC_REG

  1. Au lancement, medoc_reg() et principaux_facteurs() chargent les deux fichiers Excel.
  2. dci_df() construit le tableau des DCI (effectif, tri décroissant, sans “Total”).
  3. L’utilisateur clique sur une ligne → selected_dci() retourne la DCI.
  4. Les 7 réactives de données calculent chacune leurs effectifs / pourcentages pour cette DCI (avec, pour les graphiques en barres, le double mode molécule / ensemble des cas).
  5. Les 7 renderPlotly produisent les graphiques (camemberts ou barres horizontales), affichés dans la grille responsive de la zone inférieure.
  6. Pour le graphique facteur, la checkbox permet de déplier les 29 facteurs et ajuste la hauteur de la carte.

Remarque sur les autres onglets : mod_lib_code_atc.R et mod_focus_ipp_laxa_cortico.R reproduisent exactement la même logique, avec simplement des sources de données et des indices de colonnes différents (cf. read_lib_code_atc() et read_focus_ipp_laxa_cortico() dans R/read_data.R, ainsi que les colonnes dédiées aux facteurs et au type de prise de chaque fichier).

Module ORIGINE MÉSUSAGE (R/mod_origine_mesusage.R)

L’onglet ORIGINE MÉSUSAGE reproduit la même logique que les onglets précédents, avec pour seul critère de sélection l’origine du mésusage (au lieu de la DCI / du libellé ATC / du focus).

1. UI : mod_origine_mesusage_ui(id)

  • Zone supérieure (.zone-tableau) : uiOutput("etat") + DTOutput("table_origine"), qui liste les 3 origines avec leur libellé court (origine_libelle_court()) et leur effectif total, triées par effectif décroissant.
  • Zone inférieure (.zone-graphiques) : titre « Détail de l’origine sélectionnée », uiOutput("plot_msg"), puis un fluidRow responsive contenant 6 cartes graphiques (le 4e graphique « origine » est volontairement absent, l’origine étant précisément le critère de sélection) :
Carte plotlyOutput Contenu
1 plot_genre Camembert du genre (Homme / Femme / Autre).
2 plot_enceinte Camembert « enceinte » (Oui / Non / Non renseigné).
3 plot_age Barres horizontales des âges (2 niveaux).
5 plot_type Barres horizontales du type de mésusage (2 niveaux).
6 plot_facteur Barres horizontales des facteurs (checkboxInput + uiOutput("plot_facteur_ui")).
7 plot_type_prise Barres horizontales du type de prise (2 niveaux).

2. Server : mod_origine_mesusage_server(id)

  • origine_data() : charge origine_du_mesusage.xlsx (read_origine_mesusage()), ajoute une colonne Origine (libellé complet, colonne B / index 2) pour identifier chaque ligne, et une colonne Type_donnee.
  • principaux_facteurs() : charge principaux_facteurs.xlsx (read_principaux_facteurs()) au même moment que origine_du_mesusage.xlsx (nécessaire au 6e graphique).
  • origine_df() : ne conserve que les lignes Type_donnee == "effectif" hors ligne agrégée « Total », associe le libellé court (origine_libelle_court()) et trie par effectif décroissant.
  • selected_origine() : libellé complet de l’origine cliquée (index table_origine_rows_selected) ; selected_origine_court() en fournit la version courte.
  • genre_values() / enceinte_values() : camemberts 1 et 2 (index 5-7 et 8-10 de la ligne « effectif » de l’origine).
  • age_values() / type_values() / type_prise_values() : barres à 2 modes (index 11, 13-20 / 40-50 / 24-30), comme dans les onglets précédents.
  • facteur_values() : barres des facteurs. La liaison se fait par la colonne dédiée parmi les colonnes U→W (indices 21 à 23) de principaux_facteurs : l’en-tête (ligne 2) de la colonne vaut exactement le libellé complet de l’origine. Les libellés courts sont appliqués par position (ordre du fichier), pour robustesse face aux espaces insécables.
  • facteur_height() / facteur_plot_data() : pilotent la hauteur (15 premiers facteurs vs dépliés) et le sous-ensemble affiché du 6e graphique.

Le reste (traces plotly, libellés courts appliqués par position, retour exposé pour testServer) est identique aux modules MEDOC_REG / LIB_CODE_ATC / FOCUS.

3. Titres des graphiques multi-lignes

Les titres des 6 graphiques de l’onglet (genre, « enceinte », âge, type, type de prise, facteur) peuvent dépasser la largeur de la carte (ex. « Répartition par âge — Au moment de la dispensation en pharmacie »). Ils sont donc affichés sur 2 à 3 lignes pour en montrer l’intégralité, via deux helpers définis dans R/colors.R :

  • wrap_titre(x) : découpe chaque titre sur 2-3 lignes en insérant des <br> (réutilise la logique de wrap_libelle() avec une largeur de ligne plus généreuse, max_width = 30).
  • titre_margin_top(x) : calcule la marge supérieure t (en px) nécessaire pour accueillir le titre sur son nombre de lignes (base = 50 + par_ligne = 20 par ligne supplémentaire).

Dans chaque plotly::layout(...) du module origine, on applique :

titre <- wrap_titre(paste("Répartition par … —", origine))
p %>% plotly::layout(
  title = titre,                                  # chaîne avec <br> (multi-lignes)
  margin = list(l = 20, r = 20, t = titre_margin_top(titre), b = 20),
  ...
)

Point important : on passe le titre en chaîne simple (title = titre), sans automargin = TRUE. En cumulant automargin (qui calcule lui-même une marge) et une marge manuelle t = titre_margin_top(titre), les deux marges s’additionnaient : le titre était poussé trop haut et la première ligne sortait de la carte par le haut. En ne réservant que la marge manuelle calculée, le titre multi-lignes reste intégralement contenu dans la carte.
